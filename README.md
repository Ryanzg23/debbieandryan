# Ryan & Debbie — Wedding Site

A single-file, elegant/romantic wedding website with a password-gated planning dashboard
(guest list + checklist), backed by Supabase. Deploys to Cloudflare Pages with no build step.

## Files
- `index.html` — the entire site (public pages + dashboard). Everything editable lives in the
  `CONFIG` block near the bottom of the file (names, date, story, venues, schedule, gallery,
  passphrase, Supabase keys).
- `README.md` — this file.

## 1. Set up the RSVP table (one-time)
The public RSVP form writes to a new `rsvps` table. Open your Supabase project →
**SQL Editor** → run:

```sql
create table if not exists public.rsvps (
  id          bigint generated by default as identity primary key,
  name        text not null,
  email       text,
  side        text,
  attending   boolean default true,
  guest_count integer default 1,
  meal        text,
  message     text,
  created_at  timestamptz default now()
);

-- Let the public (anon / publishable key) submit RSVPs, but not read them back.
alter table public.rsvps enable row level security;

create policy "anyone can submit an rsvp"
  on public.rsvps for insert
  to anon
  with check (true);
```

### To see RSVPs in the site's Planning Dashboard (RSVPs tab)
The dashboard reads responses with the public key, so add a read policy too:

```sql
create policy "read rsvps"
  on public.rsvps for select
  to anon
  using (true);
```

Note: like the guest list, this makes RSVP rows readable by anyone who has the publishable
key and knows the table — the dashboard passphrase only hides the UI. That's fine for a
wedding site; for stricter privacy later, move these reads behind an authenticated role.
You can always also view RSVPs in the Supabase **Table Editor** (owner access ignores RLS).

## 2. Edit your details
Open `index.html`, find the `const CONFIG = { ... }` block, and change:
- `weddingDate` — **important**, powers the countdown (ISO format, e.g. `2026-12-12T14:00:00`)
- `dateDisplay`, `location`, couple names, story, `events`, `timeline`, `gallery` image URLs
- `dashboardPassphrase` — **change this** from the default `forever`

Gallery/story photos: paste direct image URLs (e.g. Supabase Storage public links or any host).
Empty strings show tasteful placeholders.

## 3. Deploy to Cloudflare Pages
**Option A — drag & drop (fastest):**
1. Go to Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
2. Upload this folder (containing `index.html`).
3. Deploy. You get a `*.pages.dev` URL.

**Option B — Git:** push this folder to a GitHub repo, connect it in Pages, leave build
command empty and output directory as `/` (root). Pages serves `index.html` automatically.

## Notes on data & security
- The guest list / checklist dashboard is hidden behind a client-side passphrase. This keeps it
  off the public pages, but the Supabase **publishable key** in the file can still read the
  `guests`/`wedding_checklist` tables if someone inspects the source — exactly as your current
  site already works. For real privacy later, enable Row Level Security on those tables and move
  reads behind an authenticated role.
- Tables used: `guests` (id, name, category, guest_side['groom'|'bride'], created_at, updated_at),
  `wedding_checklist` (id, side['groom'|'bride'|'wedding'], item, completed, sort_order, updated_at),
  `rsvps` (created above). All your existing 74 guests and checklist items are reused as-is.
